# Тестовое задание: регистрация, авторизация и профиль пользователя

Проект на нативном PHP 8.2 без фреймворков и сторонних библиотек. Реализованы формы регистрации и авторизации, страница профиля с редактированием данных, защита от неавторизованного доступа и интеграция Yandex SmartCaptcha.

## Требования задания и их реализация

### Форма регистрации
Пользователь указывает **имя, телефон, email, пароль и повтор пароля**.

- Все поля обязательны, пустые значения отбрасываются.
- Телефон нормализуется (приводится к единому формату) и валидируется.
- Email приводится к нижнему регистру и проверяется через `filter_var`.
- Пароль проверяется на минимальную длину (6 символов).
- Повтор пароля сравнивается с основным полем; при несовпадении показывается ошибка.

### Уникальность телефона и email
- Перед вставкой в базу выполняется `SELECT` по телефону и email.
- Если найден совпадающий телефон — пользователь видит: «Пользователь с таким номером телефона уже существует.»
- Если найден совпадающий email — пользователь видит: «Пользователь с таким email адресом уже существует.»
- Дополнительно в MySQL на колонках `phone` и `email` установлены уникальные индексы (`UNIQUE`) как страховка от дубликатов на уровне БД.

### Совпадение паролей
- Проверяется до обращения к базе: если `password !== password_confirm`, регистрация не происходит.
- Пользователю показывается сообщение «Пароли не совпадают.»

### Авторизация по телефону или email
- В форме авторизации одно поле «Телефон или Email».
- `AuthService::login` определяет, чем является введённое значение (телефон или email), и ищет пользователя по соответствующему полю.
- Пароль проверяется через `password_verify`.

### Yandex SmartCaptcha
- На странице авторизации подключён виджет SmartCaptcha (`https://smartcaptcha.cloud.yandex.ru/captcha.js`).
- При отправке формы токен капчи передаётся в поле `smart-token`.
- Серверная проверка: POST-запрос на `https://smartcaptcha.cloud.yandex.ru/validate` с передачей `secret`, `token` и IP пользователя.
- При недоступности сервиса капчи (HTTP не 200) пользователь пропускается — это рекомендация из документации Yandex (fail-open).

### Страница профиля (только для авторизованных)
- Доступ к `profile.php` возможен только при активной сессии.
- Неавторизованные пользователи перенаправляются на главную (`index.php`).
- На странице можно изменить имя, телефон, email и пароль.
- При смене пароля поля «новый пароль» и «повтор» проверяются на совпадение и минимальную длину.
- Если поля пароля оставлены пустыми — пароль не меняется.
- После сохранения данные обновляются в базе, страница перезагружается с сообщением об успехе.

### Безопасность
- Пароли хранятся в виде хешей (`password_hash` с `PASSWORD_DEFAULT`).
- Вывод пользовательских данных экранируется через `htmlspecialchars` с `ENT_QUOTES`.
- Сессия регенерируется при входе (`session_regenerate_id(true)`) — защита от session fixation.
- При каждом запросе проверяется, существует ли пользователь из сессии в базе; если нет — сессия сбрасывается.
- SQL-запросы построены через prepared statements (PDO), параметры передаются отдельно — защита от SQL-инъекций.

## Стек

- PHP 8.2
- Nginx 1.25
- MySQL 8.0
- Docker Compose
- Нативный PHP, без фреймворков и сторонних пакетов

## Структура проекта

- **Окружение (Docker)**
  - `docker/php/Dockerfile` — PHP 8.2-fpm-alpine, GD, pdo_mysql, Composer
  - `docker/nginx/default.conf` — Nginx: root, обработка статики, передача PHP в FPM
  - `docker/mysql/init.sql` — таблица `users`, UNIQUE на `phone` и `email` (гарантия уникальности)
- **Публичные страницы**
  - `public/register.php` — форма регистрации (имя, телефон, email, пароль x2)
  - `public/login.php` — авторизация по телефону/email + Yandex SmartCaptcha
  - `public/profile.php` — профиль: редактирование данных и смена пароля
  - `public/logout.php` — выход из сессии
- **Бизнес‑логика**
  - `src/AuthService.php` — регистрация, вход, обновление профиля, проверка уникальности в БД
  - `src/CaptchaService.php` — серверная валидация токена капчи
  - `src/Database.php` — PDO, подготовленные выражения (защита от SQLi)
  - `src/SessionHelper.php` — защита страниц: редирект неавторизованных на главную
  - `src/Validator.php` — валидация, нормализация телефона, проверка совпадения паролей
  - `src/Helpers.php` — экранирование вывода (`htmlspecialchars` + `ENT_QUOTES`)
- **Статика и конфиги**
  - `assets/style.css` — стили
  - `.env.example` — переменные окружения
  - `docker-compose.yml` — запуск стека одной командой

### Как запустить проект?

1. Клонируйте репозиторий и перейдите в ветку `dev`, либо оставайтесь в `master` :
   ```bash
   git clone <URL>
   cd <папка_проекта>
   git checkout dev

2. Запустите контейнеры:
   ```bash
      docker compose up -d --build
3. Откройте в браузере: http://localhost:8080
   
## Маршруты URL
- /index.php —	Главная страница. Показывает приветствие и навигацию.
- /register.php —	Регистрация нового пользователя.
- /login.php —	Авторизация с Yandex SmartCaptcha.
- /profile.php —	Профиль (только для авторизованных). Редактирование данных и смена пароля.
- /logout.php —	Выход из сессии. Редирект на главную.
## Переменные окружения (.env)

- DB_HOST —	Хост MySQL (в Docker — mysql)
- DB_PORT —	Порт MySQL (по умолчанию 3306)
- DB_NAME —	Имя базы данных
- DB_USER —	Пользователь БД
- DB_PASSWORD —	Пароль БД
- SMARTCAPTCHA_CLIENT_KEY —	Ключ клиента для виджета капчи
- SMARTCAPTCHA_SECRET_KEY —	Секретный ключ для серверной проверки капчи

## Инициализация базы данных
При первом запуске MySQL-контейнер выполняет docker/mysql/init.sql, который создаёт таблицу users с колонками:

- id — AUTO_INCREMENT, PRIMARY KEY
- name — VARCHAR
- phone — VARCHAR, UNIQUE
- email — VARCHAR, UNIQUE
- password_hash — VARCHAR
- created_at — DATETIME

## Что проверить
- Зарегистрируйте пользователя на /register.php — укажите все поля.

- Попробуйте зарегистрировать ещё раз с тем же телефоном или email — увидите сообщение о дубликате.

- Войдите через /login.php — капча должна появиться в форме.

- Откройте /profile.php — отредактируйте имя, телефон или email.

- Попробуйте сменить пароль (заполните оба поля) и затем перезайти.

- Выйдите через /logout.php и попробуйте открыть /profile.php — должен быть редирект на главную.
